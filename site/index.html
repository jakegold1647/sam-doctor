LOCAL AWS DEPLOYMENT DIAGNOSTICS

Debug AWS SAM, CloudFormation, and GitHub Actions deployment failures.

SAM Doctor reads a deployment log on your machine, identifies supported SAM, CloudFormation, IAM, and GitHub Actions OIDC failure patterns, and produces evidence, safe checks, and a shareable Markdown report.

WHO THIS IS FOR

Use it if you need a fast first-pass on deployment failures.

  • Works best for failed SAM, CloudFormation, IAM, and GitHub Actions deployments with clear error lines.
  • Not for account-state inspection, drift analysis, or automatic remediation.
  • Best when a teammate has one concrete failing run you need triaged quickly.

GET STARTED

Install v0.7.7 in one command.

python -m pip install sam-doctor

This installs the latest stable release from PyPI. Then run sam-doctor demo to see a local example, or pass a log to sam-doctor diagnose deployment.log.

60-SECOND FIRST RESPONSE

Diagnose a teammate's failure in under two minutes.

sam-doctor diagnose deployment.log --format markdown
  1. Run the command from the shared log or pasted excerpt.
  2. Send back one finding (or say no supported signal found).
  3. Include one safe verification command and ask for one follow-up.

For stdin workflows, use sam-doctor diagnose - --format markdown. If you still can't match the failure, open Report a bad diagnosis.

GITHUB ACTIONS

Keep the diagnostic close to the failed workflow.

- name: Deploy
  shell: bash
  run: |
    set -o pipefail
    sam deploy --no-confirm-changeset 2>&1 | tee deployment.log

- name: Diagnose deployment log
  if: always()
  id: sam-doctor
  uses: jakegold1647/sam-doctor@v0.7.7
  with:
    log-file: deployment.log
    summary: true
    # fail-on-findings: true

Put the action after the command that writes the log and keep if: always(), or GitHub skips it when deployment fails. It exposes finding-count and has-findings outputs; job summaries and failure gating are opt-in. Uncomment fail-on-findings: true when a supported diagnosis should fail the job.

Download the same starter as a base workflow: sam-doctor GitHub Actions starter.

For shell-based CI, run sam-doctor diagnose deployment.log --format json --output diagnosis.json --fail-on-findings. It writes the report and returns status 1 only when a supported finding is present.

WHAT IT HANDLES NOW

Start with the failures that waste deployment time.

  • GitHub Actions OIDC and role-assumption failures
  • GitHub Actions job summaries and opt-in CI gating
  • IAM access-denied errors
  • CloudFormation rollback states
  • CloudFormation capability acknowledgement errors
  • Template, IAM trust-policy, and deployment-artifact errors
  • SAM configuration and change-set failures
  • API Gateway CORS preflight conflicts

WHAT IT DOES NOT DO

Useful without pretending to be magic.

  • No AWS account access or automatic remediation
  • No claim of guaranteed root-cause analysis
  • No replacement for a security review or production operator
  • No raw-log upload or cloud processing

A SMALL, USEFUL LOOP

From noisy log to next check.

  1. Give it a log. Point the CLI at a file or pipe text through stdin.
  2. See the evidence. Matching lines are redacted and kept short.
  3. Verify the cause. Use the linked docs and review every suggested change.

Common AWS deployment questions

What does SAM Doctor diagnose'

It recognizes explicit AWS SAM, CloudFormation, IAM, API Gateway, and GitHub Actions deployment failure patterns, including AssumeRoleWithWebIdentity, InsufficientCapabilitiesException, rollback states, and ECR image access failures.

Does SAM Doctor access AWS or upload logs'

No. The CLI and core diagnostic logic process the text locally. They do not call AWS, upload logs, change resources, or make an automatic fix.

What should I do with a CloudFormation ROLLBACK_COMPLETE error'

Find the earliest related CREATE_FAILED or UPDATE_FAILED resource event first. Run the sanitized status reason through SAM Doctor, then verify the underlying service cause before retrying.

Can SAM Doctor prove the root cause'

No. It reports only what a matched text pattern supports and labels confidence. Use its safe checks and official documentation to confirm the diagnosis before changing a policy or stack.
