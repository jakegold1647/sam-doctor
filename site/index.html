LOCAL AWS DEPLOYMENT DIAGNOSTICS

Find the next useful step in a failed AWS deployment.

SAM Doctor reads a deployment log on your machine, identifies supported SAM, CloudFormation, IAM, and GitHub Actions OIDC failure patterns, and produces evidence, safe checks, and a shareable Markdown report.

Try the free alpha Help shape the next version

Runs locally. No AWS credentials. No log upload. No automatic changes.

$ sam-doctor diagnose failed-deploy.log --format markdown

Likely cause - high confidence

GitHub Actions cannot assume the configured AWS role through OIDC.

Evidence: Not authorized to perform: sts:AssumeRoleWithWebIdentity

Next: verify id-token: write, the OIDC audience, and the trust policy subject condition.

WHAT IT HANDLES NOW

Start with the failures that waste deployment time.

  • GitHub Actions OIDC and role-assumption failures
  • IAM access-denied errors
  • CloudFormation rollback states
  • SAM configuration and change-set failures
  • API Gateway CORS preflight conflicts

WHAT IT DOES NOT DO

Useful without pretending to be magic.

  • No AWS account access or automatic remediation
  • No claim of guaranteed root-cause analysis
  • No replacement for a security review or production operator
  • No raw-log upload or cloud processing

A SMALL, USEFUL LOOP

From noisy log to next check.

  1. Give it a log. Point the CLI at a file or pipe text through stdin.
  2. See the evidence. Matching lines are redacted and kept short.
  3. Verify the cause. Use the linked docs and review every suggested change.

Questions

Does SAM Doctor upload my logs?

No. The free alpha processes the file locally. Review any report before sharing it outside your team.

Can it change IAM policies or deploy resources?

No. It provides evidence and read-only verification steps only. You remain responsible for every change.

Who is it for?

Solo developers, freelancers, and small teams that deploy Python or other applications through AWS and GitHub Actions.
