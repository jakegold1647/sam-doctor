ERROR REFERENCE

API Gateway's control plane throttled the deployment

The template is fine. API Gateway refused the calls that were creating it, and the same deployment succeeds once the call rate drops.

WHAT IT MEANS

What this error means

CREATE_FAILED  AWS::ApiGateway::RestApi  Api  Too Many Requests (Service: ApiGateway, Status Code: 429)
An error occurred (TooManyRequestsException) when calling the CreateDeployment operation: Too Many Requests

API Gateway's control plane — the API that creates and modifies APIs, not the one serving traffic — throttles far more aggressively than CloudFormation's. Two situations reach the limit:

  • One large template. A stack creating many resources, stages, or usage plans issues a burst of control-plane calls on its own, without any parallelism involved.
  • Parallel deploys. Matrix jobs or monorepo fan-out deploying into the same account and Region share one throttle, so each deploy is fine in isolation and they fail together.

The trap is how it presents: it arrives as CREATE_FAILED on a template resource, which reads like a template error. That sends people editing YAML that was never wrong. Then unbounded CI retries hammer the same throttle and extend the outage they were meant to ride out.

Other services return TooManyRequestsException as well — Lambda among them. The Service: field in the error names which one answered.

FIX

How to fix it

  1. Retry once, after a pause, with backoff. Not an immediate loop — retrying instantly keeps the throttle engaged and turns a short delay into a long one.
  2. Serialize deploys that create API Gateway resources in the same account and Region. In GitHub Actions that means a concurrency group rather than a matrix: 
    concurrency:
  group: deploy-${{ github.ref }}
  cancel-in-progress: false
  3. Count what one deployment creates. If a single stack builds many APIs, stages, or usage plans at once, splitting it spreads the calls out and removes the burst.
  4. Only then look at quotas. If this happens at a steady rate rather than in bursts, check the API Gateway control-plane limits in Service Quotas — but bursty failures are a shape problem, not a quota problem.

AUTOMATE THE TRIAGE

Diagnose this automatically

SAM Doctor names control-plane throttling (medium confidence) instead of reporting a resource failure, so the log says "retry" rather than sending you into the template. Runs locally; no AWS access, no log upload. 

python -m pip install sam-doctor
sam-doctor diagnose deployment.log --format markdown

RELATED

Related errors

  • Rate exceeded / Throttling — the same condition at the CloudFormation layer.
  • The REST API doesn't contain any methods — an API Gateway failure that is the template.
  • An IAM policy quota was exceeded — a limit that retrying will never clear.
