ERROR REFERENCE

An IAM policy size or attachment quota was exceeded

Nothing was denied here. IAM accepted the request and refused it on a quota, which is why permission advice does not help — and why the fix depends entirely on which quota the error names.

WHAT IT MEANS

What this error means

CREATE_FAILED  AWS::IAM::Policy  FunctionPolicy  Maximum policy size of 6144 bytes exceeded for role my-function-role (Service: Iam, Status Code: 409)
An error occurred (LimitExceeded) when calling the AttachRolePolicy operation: Cannot exceed quota for PoliciesPerRole: 10

Growing templates arrive here quietly. Every function adds policy, and the deploy that fails is whichever one crossed the line — not the change that caused the growth. Three different quotas produce this error and only one of them can be raised:

  • The document is too large. A managed policy allows 6,144 characters; all inline policy on a role allows 10,240 in total. These are hard limits. A quota-increase request against them will be refused.
  • Too many policies are attached. PoliciesPerRole defaults to 10 and is adjustable — the one case where asking for an increase is a real answer rather than a workaround.
  • Too many versions exist. A managed policy keeps 5 versions. Deleting the ones no longer in use is safe and takes effect immediately.

One detail catches people out on the size limits: SAM expands policy templates, so the document IAM receives is larger than the one written in template.yaml. Measuring the source will make the limit look further away than it is.

FIX

How to fix it

  1. Read the quota name before changing anything. PolicySize, PoliciesPerRole and PolicyVersionsInUse need different fixes, and only the middle one is adjustable.
  2. For an attachment quota, see what is already attached and consolidate before requesting an increase: 
    aws iam list-attached-role-policies --role-name my-function-role
  3. For a version quota, prune old versions. This is the cheapest of the three fixes and carries no design decision: 
    aws iam list-policy-versions --policy-arn arn:aws:iam::123456789012:policy/my-policy
aws iam delete-policy-version --policy-arn arn:aws:iam::123456789012:policy/my-policy --version-id v2
  4. For a size quota, reduce the rendered document. Split the policy across resources, consolidate statements that share the same actions and resources, or use a wildcard deliberately where the resource list is what keeps growing. Widening a policy to fit a limit is a security decision — make it on purpose, not to get a deploy through.
  5. Request an increase in Service Quotas only for the attachment quota. The size limits are hard; a request there costs a round trip and returns a refusal.

AUTOMATE THE TRIAGE

Diagnose this automatically

SAM Doctor names the IAM quota (high confidence) rather than reporting a generic resource failure, and separates the three cases so the advice matches the quota. Runs locally; no AWS access, no log upload. 

python -m pip install sam-doctor
sam-doctor diagnose deployment.log --format markdown
